## 2. 没有 Mac 设备怎么办 → GitHub Actions 的 macOS runner

- **electron-builder 不能在 Windows 上构建 macOS 目标**（需要 macOS 的 `codesign` / `hdiutil` 等工具链）。
- **GitHub Actions 对 public 仓库的标准托管 runner 完全免费**（含 macOS）→ 这就是"没有 Mac 也能出 Mac 版"的方案。
- 已提供 `.github/workflows/build.yml`：`verify`（typecheck + 单测 + E2E）→ `package`（windows / macos-arm64 / macos-x64 矩阵）→ `release`（打 `v*` tag 时建 Release 草稿）。

> 私有仓库：macOS runner 按 10 倍扣免费额度（2000 分钟/月 ≈ 200 macOS 分钟），容易超；想省钱就把仓库设为 public。

**备选**：让 Mac 用户在本地源码构建（`npm install && npm run build` + `npx electron-builder --mac`）——本地构建的 App **没有 quarantine 标记**，可直接打开，完全绕开 Gatekeeper。

## 3. macOS 支持需要改的 5 处（精确到文件）

### 3.1 `package.json`：加 `mac` 段 + `pack:mac` 脚本

```jsonc
"build": {
  // ...现有 appId / productName / directories / files / win / nsis 保持不变
  "mac": {
    "icon": "resources/icon.png",
    "category": "public.app-category.productivity",
    "target": [
      { "target": "dmg", "arch": ["arm64", "x64"] },
      { "target": "zip", "arch": ["arm64", "x64"] }
    ]
  }
}
```
```jsonc
"scripts": {
  // ...现有脚本保持不变
  "pack:mac": "npm run clean:dist && npm run prepare:electron-dist && npm run build && npm run rebuild:electron && electron-builder --mac"
}
```

⚠️ **不要写 `"identity": null`**：那会完全跳过签名，Apple Silicon（arm64）上未签名的 App **根本无法启动**。
正确做法是不设 `identity`，在 CI 里设 `CSC_IDENTITY_AUTO_DISCOVERY: "false"` —— 此时 electron-builder 对 **arm64/universal 自动做 ad-hoc 签名**（官方行为），应用能跑，只是没公证。

### 3.2 `scripts/prepare-electron-dist.mjs`：zip 名平台化（关键）

现状写死了 Windows：
```js
const zipName = `electron-v${version}-win32-x64.zip`;
const cacheRoot = path.join(os.homedir(), "AppData", "Local", "electron", "Cache");
```
**原理**（已在 `node_modules/app-builder-lib/out/electron/ElectronFramework.js:136` 确认）：
`electronDist` 指向的目录里，electron-builder 会找名为
`electron-v<version>-<platform>-<arch>.zip` 的文件（platform = `win32` / `darwin` / `linux`）。
所以 macOS 必须提供 `electron-v35.7.5-darwin-arm64.zip`。

改法：
```js
const platformName = process.platform === "win32" ? "win32"
  : process.platform === "darwin" ? "darwin" : "linux";
const archName = process.arch === "arm64" ? "arm64" : "x64";
const zipName = `electron-v${version}-${platformName}-${archName}.zip`;

// 跨平台缓存目录（macOS: ~/Library/Caches/electron）
const cacheRoot = process.platform === "darwin"
  ? path.join(os.homedir(), "Library", "Caches", "electron")
  : path.join(os.homedir(), "AppData", "Local", "electron", "Cache");
```
（下载 URL 无需改：npmmirror 与 GitHub 都有 darwin-zip。）

### 3.3 `scripts/verify-pack.mjs`：支持 `.app`

现状写死 `dist/win-unpacked/*.exe` 且用 `taskkill`。改法：
```js
// 产物定位
if (process.platform === "darwin") {
  const product = pkg.build?.productName ?? pkg.name;
  for (const dir of ["mac-arm64", "mac", "mac-universal", "mac-x64"]) {
    const p = path.join(ROOT, "dist", dir, `${product}.app`, "Contents", "MacOS", product);
    if (fs.existsSync(p)) return p;
  }
}
// 结束进程
process.platform === "darwin"
  ? spawn("pkill", ["-f", exe])
  : spawn("taskkill", ["/PID", String(child.pid), "/T", "/F"]);
```
（macOS 的 `.app` 内可执行文件路径是 `Contents/MacOS/<ProductName>`，没有 `.exe`。）

### 3.4 `resources/`：macOS 图标需要 ≥1024

当前 `icon.png` 只有 **256×256**，electron-builder 生成 `.icns` 会失败/糊。
- 换一张 **1024×1024 PNG**（`resources/icon.png`），并把 `mac.icon` 指向它；或
- 直接放 `resources/icon.icns` 并 `mac.icon: "resources/icon.icns"`。

### 3.5 （可选）`src/main/index.ts`：错误文案通用化

`safeStorage` 本身跨平台（Windows→DPAPI，macOS→Keychain），**代码无需改**。只是启动失败提示写死了「DPAPI」：
```
'系统加密服务不可用（DPAPI）…'
```
建议改为「系统安全存储不可用」，避免 Mac 用户困惑。同理 `win32` 的 `setAppUserModelId` 已有平台判断，无需动。

## 4. 没有 Apple Developer 账户会怎样

### 4.1 失去什么
- **不能签名**（Developer ID）→ 用户看到「来自身份不明的开发者」。
- **不能公证**（notarization）→ Gatekeeper 拦截。公证必须是 Apple Developer Program 成员（个人 $99/年），没有免费路径。

### 4.2 还能得到什么
- arm64/universal 构建会**自动 ad-hoc 签名** → 应用**能启动**，只是首次打开需手动放行。
- 所以：**不花钱也能发布可用的 Mac 版**（体验略糙）。

### 4.3 必须写进 README / Release 说明的放行步骤
**情况一：提示「xxx 已损坏，无法打开」**（最常见，其实是 quarantine 标记）
```bash
sudo xattr -dr com.apple.quarantine "/Applications/HHmail.app"
```
**情况二：提示「来自身份不明的开发者」/「Apple 无法检查是否包含恶意软件」**
- 「系统设置 → 隐私与安全性」→ 点 **「仍要打开」** → 再确认。
- 新版 macOS 已不能用"右键 → 打开"绕过，以上面为准。

### 4.4 分发格式
- **优先 `.zip`**（而不是 `.dmg`）：未签名应用用 zip 分发更少踩「已损坏」的坑。
- Release 里同时附 Windows `.exe` 与 mac 的 `-arm64.zip` / `-x64.zip`。

### 4.5 以后想升级体验
- 加入 Apple Developer Program 后，在仓库 Secrets 配 `CSC_LINK` / `CSC_KEY_PASSWORD`（签名）与 `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID`（公证），CI 里去掉 `CSC_IDENTITY_AUTO_DISCOVERY: "false"` 并加公证配置即可，工作流结构不用改。

## 5. CI 工作流（已提供）

`.github/workflows/build.yml`：
- `verify`：`npm ci` → `npm run typecheck` → `npm test` → `npm run test:e2e`（windows runner，因 E2E 需要系统 Edge）。
- `package`：矩阵 `windows-latest --win --x64` / `macos-latest --mac --arm64` / `macos-13 --mac --x64`，依次执行 `clean:dist → prepare:electron-dist → build → rebuild:electron → electron-builder → verify-pack.mjs`，上传产物。
- `release`：`v*` tag 时创建 Release 草稿并附上所有产物 + 安装说明。

> 该工作流假设 §3 的改动已完成；否则 macOS 任务会在"准备 Electron zip / verify-pack"处失败（Windows 任务不受影响）。
