# HHmail 功能路线图

> **说明（现状）**：本文是早期（P0/只读阶段）的设计与调研文档，当时只做只读收信；
> 当前版本已支持**发信**（回复 / 转发 / 新写 / 草稿，SMTP + XOAUTH2 或个人邮箱 SMTP），
> 收信侧仍保持只读（不改动服务端邮件）。功能现状以 README 与使用说明为准。

> 说明：本文是开发过程记录，早期按「V2」分阶段命名；对外版本号从 **1.0.0** 起。

> 基于 `program/` 当前实现（M0–M3 已交付，含 AI 总结、设置、通知、托盘、打包）与 `README.md` 的已知限制。
> 本文件是**建议方向**，供你审批；按下面分档推进，每档内部顺序可由你调整。

---

## 0. 当前已具备（V1 / MVP）

- 设备码登录 + XOAUTH2 + Token 续期（DPAPI 落盘）
- 只读同步 INBOX（全量历史 + 增量 UID 状态机）
- 本地线程聚合 + SQLite/FTS5 索引
- 收件箱列表、邮件详情、AI 单封/线程总结（可持久化、可自定义提示词）
- 设置页（AI 模型/Key/总结提示词/加载图片/同步范围/自动刷新/新邮件通知）
- Windows 系统通知、托盘后台、单实例、DOMPurify HTML 净化
- L1 单测 + L2 renderer E2E + L3 Electron 冒烟 全部通过；已打包安装包/便携版

## 1. 结论摘要

| 优先级 | 类别 | 是否需写权限 | 建议 |
|---|---|---|---|
| **P0（推荐先做）** | 补齐 MVP 缺口 | 否 | AI 搜索问答、附件下载 UI、更多文件夹 |
| **P0（推荐）** | 收件箱效率（Notion 风格核心） | 否（本地） | 自定义视图、标签/标星、稍后提醒、批量/快捷键 |
| **P0（推荐）** | AI 读侧增强 | 否（外部 API） | 续写、一键回复草稿、行动项提取、智能视图、自动摘要 |
| **P1（需先确认授权）** | 写信/发送 | **是** | Graph Mail.Send 或 SMTP AUTH，先解决 学校 授权 |
| **P1** | 平台/工程 | 否 | 多账户、数据导出/备份、自动更新、i18n、CJK 搜索改进 |

> **关键判断**：V2 应优先把「**读侧产品力 + AI**」做深，这是**零权限风险、见效最快**的部分；
> 写信/发送（P1）是分水岭，**在确认 学校 是否允许 Graph/SMTP 授权前不要动**，否则会卡在外部审批上。

## 2. P0 —— 补齐 MVP 缺口（低风险、快）

| 功能 | 现状 | 难度 | 说明 |
|---|---|---|---|
| **AI 搜索问答**（M7） | 未实现 | ★★☆ | 原批准 MVP 已含但未交付。复用已有 FTS5 索引做 RAG：检索 Top-K → DeepSeek 生成带引用的回答。**建议作为 V2 第一条。** |
| **附件下载 UI 接入** | `fetchAttachment` 已实现，UI 未接 | ★☆☆ | 把详情页附件改成点击即下载/打开，收益立竿见影。 |
| **多文件夹读取** | 仅 INBOX | ★★☆ | 只读拉取「已发送/归档/草稿」等文件夹（仍只读，不改服务端）。 |

## 3. P0 —— 收件箱效率（Notion Mail 差异化核心，纯本地）

> 这些是 Notion Mail「像数据库一样管理收件箱」的灵魂，全部本地实现，不碰服务端写操作。

| 功能 | 难度 | 说明 |
|---|---|---|
| **自定义视图 / 保存视图** | ★★☆ | 按发件人/日期/未读/标签/关键字筛选 + 排序，可命名保存到侧边栏。 |
| **本地标签 / 星标** | ★★☆ | 给邮件打本地标签；侧边栏按标签筛选。 |
| **稍后提醒（Snooze）** | ★★☆ | 本地提醒队列，到点触发系统通知（复用现有通知模块）。 |
| **批量操作** | ★★☆ | Ctrl/Shift 多选 → 批量标星/加标签/标记已读（本地）/导出。 |
| **键盘快捷键** | ★☆☆ | `j/k` 上下、`Enter` 打开、`s` 星标、`/` 聚焦搜索、`a` 归档入口等。 |
| **优先级收件箱 / 置顶** | ★★☆ | 规则或 AI 打分把重要邮件置顶，减少干扰。 |

## 4. P0 —— AI 读侧增强（外接 DeepSeek，无需写权限）

| 功能 | 难度 | 说明 |
|---|---|---|
| **AI 续写 / 自动补全** | ★★☆ | 在回复/写信输入区根据已有文字续写（暂不发送，仅草稿）。 |
| **AI 一键回复 / 生成整封草稿** | ★★☆ | 由线程生成一句/整封回复草稿，填入草稿区（P1 发送前先做草稿）。 |
| **AI 行动项 / 截止日期提取** | ★★☆ | 把邮件中的待办、DDL 提取成结构化任务清单。 |
| **AI 自动分类** | ★★☆ | 自动打「学术/教务/活动/社会/通知」等标签，辅助视图。 |
| **AI 智能视图**（自然语言建） | ★★★ | 「上周导师发的未读邮件」→ LLM 转成视图条件。 |
| **新邮件自动摘要推送** | ★★☆ | 已有通知，升级为「点开即看摘要 + 跳转邮件」，分批/节流防刷屏。 |

## 5. P1 —— 写信 / 发送（需先确认 学校 授权）

> ⚠️ 这是 V2 里**唯一需要外部权限**的分支。在确认可行前，仅在 UI 预留入口。

| 功能 | 难度 | 依赖 |
|---|---|---|
| **Graph Mail.Send / SMTP AUTH** | ★★★★ | 学校 是否允许自注册 Entra 应用 或 是否放行 SMTP AUTH（需实测） |
| **写信编辑器 + 草稿库** | ★★★ | 本地存储，可先做（不依赖发送） |
| **回复 / 转发/引用** | ★★★ | 依赖发送 |
| **签名 / 模板** | ★★☆ | 本地 |
| **定时发送 / 撤销发送** | ★★☆ / ★★★ | 本地延时 + 发送，或 Graph |
| **附件上传发送** | ★★★ | 依赖发送 |
| **群发 / 邮件合并** | ★★★ | 限速防风控 |

> 建议：**先单独确认 学校邮箱是否允许 Graph/SMTP 写权限**；若不允许，写信/发送就长期停在「草稿 + 本地」形态，不影响 P0。

## 6. P1 —— 平台 / 工程（增量，不需要外部审批）

| 功能 | 难度 | 说明 |
|---|---|---|
| **多账户**（`@link` + `@school` + 其他） | ★★★ | 多套 token + 独立同步状态；账号切换。 |
| **数据导出/备份** | ★★☆ | 导出为 EML / JSON / Markdown / 附件打包。 |
| **自动更新** | ★★☆ | `electron-updater` + 更新源；当前打包未签名，需自签或代码签名。 |
| **i18n 中英文** | ★★☆ | 渲染层文案集中到 token。 |
| **CJK 搜索改进** | ★★☆ | 当前 2 字词走 LIKE 兜底；可换 `jieba` 分词或提升 trigram 评分。 |
| **性能** | ★★☆ | 虚拟滚动（大批量邮件）、索引/清理策略、附件缓存上限。 |
| **端到端打包/签名** | ★☆☆ | 代码签名 + 自动更新配合。 |

## 7. 建议的 V2 交付顺序（里程碑）

| 里程碑 | 内容 | 预计交付 |
|---|---|---|
| **V2.0** | AI 搜索问答（M7）+ 附件下载 UI + 多文件夹只读 | 补齐 MVP 缺口 |
| **V2.1** | 自定义视图 + 标签/星标 + 稍后提醒 + 批量/快捷键 | 收件箱效率上线 |
| **V2.2** | AI 续写/一键回复草稿/行动项提取/智能视图/自动摘要 | AI 产品力强化 |
| **V2.3** | 多账户 + 数据导出/备份 + i18n + 性能优化 | 平台稳固 |
| **V2.4（可选/需授权）** | 写信/发送 + 草稿库 + 签名/模板 + 定时/撤销发送 | 视 学校 授权而定 |

## 8. 待你拍板的问题

1. **V2 先做哪几条**？（建议：V2.0 + V2.1）
2. **写信/发送**是否要纳入 V2？前提是你能确定 学校 是否允许 Graph/SMTP 授权；否则先放 V2.4。
3. **AI 智能视图 / 自动摘要**这类较重的 LLM 功能是否想先做？涉及 token 成本与延迟。
4. 是否需要**多账户**？你日常是否一个 学校邮箱就够。
