# 检索评测（M1）

目的：**用数据决定要不要上向量**。先跑一轮基线，看「关键词 + 结构化过滤 + 索引卡片」够不够；
不够再考虑本地 ONNX 小模型（见 PROJECT_MEMORY 里的 embedding 选型对比）。

## 一次评测怎么跑

```bash
# 1) 先把索引卡片建起来（应用内：设置 →「🔁 重新生成全部摘要（覆盖旧的）」）
#    摘要与索引卡片是两次独立调用，179 封 ≈ 几分钟、成本几分钱
# 2) 跑评测（自动复制一份数据库到临时目录，不碰线上数据）
npm run eval:retrieval
#    自定义 topK：
npm run eval:retrieval -- --topk 8
```

输出：
- 控制台：每题命中的来源与前三封候选（只打印 id 与主题，不打印正文）
- 报告文件：`tests/eval/report.md`（含 Recall@1 / Recall@5、命中来源分布、逐题明细）

## 怎么标注（第一轮）

`tests/eval/questions.json` 里 `expect` 一开始是空的，脚本会打印每题的候选邮件；
你看一眼候选，把**正确邮件的 id** 填进 `expect`（可多个），再跑一次就会算分：

```json
{ "q": "这周有什么截止？", "expect": [176, 179], "note": "时间窗 + 截止" }
```

## 基线记录

### 第 1 轮（索引卡片覆盖 100/182）

| 指标 | 值 |
| --- | --- |
| Recall@1（命中任一即算对的 8 题） | 25.0% |
| Recall@5 | 50.0% |
| 集合题平均覆盖率（5 题） | 42.5% → 补「广告」类型规则后 85.6% |

### 第 2 轮（索引卡片覆盖 170/178，标准答案按最新邮件重算）

| 指标 | 值 |
| --- | --- |
| Recall@1 | 25.0% |
| Recall@5 | **87.5%**（7/8；唯一未命中：图书馆） |
| 集合题平均覆盖率 | **95.2%**（本周截止 100%、下周作业 100%、奖学金 100%、广告 100%、活动 76%） |
| 命中来源 | index-filter 131 · body 42 · recent 15 · index-keyword 12 · summary 9 |

本轮修掉的两处**排序/分词**问题（都是评测暴露的）：
1. 结构化过滤路原来按 `due_ts ASC` 排序 → 老邮件（5 月/7 月截止的活动）把新邮件挤出前几名；
   改为「未来最近优先 → 过去 → 无期限」，并用 `ABS(due_ts - now)` 收敛；
2. 中文词干 3 字滑窗对「学费交」这种不连续短语必然落空 → 追加 2 字滑窗给 LIKE 兜底
   （FTS 仍只用 3 字），并修掉「什么」先于「什么时候」被删导致留下「时候」残渣的问题。

剩余弱项：**中英跨语言**（中文问「图书馆」，正文写 "Library"）——关键词/结构化都抓不到，
这是唯一还需要向量检索的场景（若后续要补，优先本地小模型，见 PROJECT_MEMORY 选型对比）。

### 第 3 轮（索引卡片覆盖 174/182：跨语言 + 简繁 + 「第一条就命中」）

| 指标 | 第 2 轮 | 第 3 轮 |
| --- | --- | --- |
| Recall@1 | 25.0% | **100%**（8/8，且全部来自真实检索，无「最近兜底」） |
| Recall@5 | 87.5% | **100%**（严格口径也 100%） |
| 集合题平均覆盖率（5 题） | 95.2% | **100%**（本周截止 / 下周作业 / 奖学金 / 活动 / 广告） |
| 命中来源 | index-filter 131 · body 42 · recent 15 · index-keyword 12 | index-keyword 199 · index-filter 121 · body 72 · summary 42 · **recent 0** |

> 口径说明：这一轮同时做了**一处标注修正**（见下），如果不算修正，Recall@1 是 87.5%（7/8）、
> Recall@5 是 87.5%——唯一"未命中"的那题其实是标注漏了正确答案。

本轮修掉的三个根因（都在**零成本**范围内，仍然不需要向量）：

1. **跨语言**：新增 `src/shared/bilingual.ts`（60+ 组校园邮件中英概念表）。
   中文问「图书馆」→ 自动补 `library`；英文问 `library hours` → 自动补「图书馆 / 圖書館」。
   同理覆盖 学费↔tuition/fees/billing、宿舍↔hostel/accommodation、实习↔internship/placement、
   考试↔exam/quiz、选课↔course registration/enrollment 等。
2. **简繁**：新增 `src/shared/zhTw.ts`（只收高置信度、无歧义的字对，如 学→學、费→費、图→圖、馆→館；
   歧义字如「注/里/台/复」不按字转，改在 `bilingual.ts` 里按词处理 注册→註冊、回复→回覆）。
   用户写简体、语料是繁體（圖書館/學費/選課）时不再 0 命中。
3. **「第一条就命中」**：新增 `src/shared/retrievalRank.ts` + `retrievalQuery.ts`：
   - 检索词带权重（用户原词 3 > 简繁变体 3 > 跨语言同义词 2 > 中文滑窗/英文前缀 1）；
   - 候选排序按「主题命中 > 卡片命中」＋**全库 IDF**（`notice/notification/course/program` 这类全库高频词降权）；
   - 重叠词只算一次（`notifications / notification / notif` 不再叠加刷分）；
   - 汇总类标题（`Daily Notifications` / `Weekly Highlights`）降权，具体邮件优先；
   - 索引卡片关键词路补了 **LIKE 兜底**（≥2 字的中文词 trigram 根本命中不了：学费/宿舍/讲座），
     并连带 `m.subject` 一起匹配（卡片没写、主题写了的也能召回）。
   - **结构化过滤路保持不动**（纯按「未来最近截止优先」列举）：它是"集合视图"，
     一旦按相关性重排，窗口内的条目会被挤出前 N（实测活动集合覆盖率 76% → 40%）。
4. **集合类问题的候选数 25 → 40**：活动集合覆盖率 84% → 100%（卡片很短，多带十几条约几 KB token）。

**标注修正（必须写明，否则数字有水分）**：
- 「语言课程或英语工作坊？」原来只标了多元文化心理支援服務的 4 封；实测库里凡是索引卡片写着
  「语言：英语」的活动类邮件（面试技巧工作坊、奖学金申请工作坊、uPals 射箭工作坊）同样满足
  「英语工作坊」，原标注会把**正确答案判成漏召回**。现已补全为 9 封并在 `questions.json` 的 note 里说明。
- 「实习或就业相关的邮件？」补上同系列但漏标的 #98（与已标的 #178/#180 是同一系列）等 4 封。

**还没解决 / 已知取舍**：
- 索引卡片质量仍是上限：模型有时把「语言：英语」这类字段写进 FACTS，会让泛化词参与打分；
  后续可在生成提示词里要求「别名/实体只写专有名词」。
- 「有没有需要回复的邮件？」「有哪些邮件带附件？」这类**意图/元数据**问题仍未建模（未标注，不计分）。

## 调试单个问题（为什么不命中）

```bash
npm run rebuild:electron && npm run build:eval
node scripts/run-eval.mjs --dbg      # 输出 tests/eval/dbg.md（gitignored）
```

`--dbg` 会打印每题的关键词/过滤条件、候选排序与得分、每个候选命中了哪些词（主题/卡片）、
以及候选卡片全文，用来定位"是召回不到，还是排序不对"。

## 判断标准（建议）

| Recall@5 | 结论 |
| --- | --- |
| ≥ 80% | 关键词 + 结构化过滤够用，**不急着上向量** |
| 60% ~ 80% | 先补索引卡片质量（别名/问题更全）与查询改写，再复评 |
| < 60% | 上向量（首选本地 ONNX 小模型，避免全量正文外发） |

## 注意

- 评测脚本用 Electron 跑（better-sqlite3 是 Electron ABI），并且**先复制一份数据库到临时目录**，不碰线上数据。
- `npm run eval:retrieval` 会 `rebuild:electron`；跑完要跑单测（`npm test` 自动 `rebuild:node`）或打包（`npm run pack` 会自动 rebuild）。
- 评测**不调用大模型**，只评检索；回答质量另看应用内 AI 助手。
- 报告文件（`tests/eval/report.md`、`suggest.md`、`dbg.md`）含邮件主题（属于你的隐私），已在 `.gitignore` 中，提交前确认别加进 git。
