# 待办重做（备忘录式）+ UI 打磨 · 设计方案（请审查）

> 目标：把现在的「自动汇总的清单页」重做成**像备忘录一样可以自己写、自己加、自己引用邮件/日历**的待办，
> 同时解决 UI「生硬、排版丑」的问题。
>
> 预览：`docs/design/tasks-memo-light.png`（亮色）/ `tasks-memo-dark.png`（暗色）
> 可交互原型：`docs/design/tasks-memo-mockup.html`（浏览器打开，按 **T** 切换亮/暗）

## 2. 现在的待办有什么问题

1. **默认全是"自动汇总"**：卡片 DUE + 摘要行动项自动变成任务，用户不能真正"拥有"自己的清单 → 本次改为**手动为主**（用户明确要求）。
2. **没有正文/清单**：只能改标题和截止，像表单不像备忘录。
3. **没有引用**：任务和原邮件、日历事件是断开的，点标题只能跳回邮件。
4. **视觉生硬**：单列大表格、灰边框、间距紧、没有层次与留白。

```
│  ☑ 待办  ├──────────────┬────────────────────────────────┤
│  🗓 日历 │ 🔍 搜索…     │  待办 · 今天 23:59      [✓] [⋯] │
│  …       │ ┌──────────┐ │  提交 Experiment 1 报告          │
│          │ │● 提交…   │ │  正文（自动保存，无保存按钮）      │
│          │ │  今天23:59│ │  ────────────────────────────  │
│          │ │  📧2 🗓1 │ │  清单  ☑ 重画图3  ☐ 补第2页 …    │
│          │ └──────────┘ │  ────────────────────────────  │
│          │ ┌──────────┐ │  引用  📧 邮件A  📧 邮件B  🗓 日历  │
│          │ │  回复 TA…│ │        ＋ 引用邮件 / 日历事件      │
│          │ └──────────┘ │  ────────────────────────────  │
│          │ …            │  ⏰ 今天 23:59   [设为完成] [删除] │
└──────────┴──────────────┴────────────────────────────────┘
```

**左栏（列表）**
- 每行：勾选圆圈、标题、正文摘要一行、徽标（截止 / 📧 N / 🗓 N）。
- 逾期红色、今天/明天橙色、完成划线灰掉。
- 选中行左侧 3px 强调色竖条 + 淡底。
- 顶部搜索框（本地过滤标题/正文/引用邮件主题），键盘 ↑↓ 切换、Enter 打开。

**右栏（备忘录编辑器）**
- 标题（单行大字号）、正文（多行，自动保存，800ms 防抖）。
- **清单**：可增删的 checkbox 子项（Enter 新建、空行 Backspace 删除）。
- **引用**：邮件卡片（主题/发件人/时间/附件数）+ 日历卡片（时间/地点/来源），可点「打开」跳转；
  `＋ 引用邮件 / 日历事件` 打开选择器。
- **底部**：截止时间、设为完成、删除。

## 4. 数据与行为

### 4.1 迁移（追加 v22）
```sql
-- tasks 扩展（保留旧列，向后兼容）
ALTER TABLE tasks ADD COLUMN body TEXT;              -- 正文
ALTER TABLE tasks ADD COLUMN checklist TEXT;         -- JSON: [{id,text,done}]
ALTER TABLE tasks ADD COLUMN updated_at ...          -- 已有
-- 引用关系（一条待办可挂多个邮件/日历事件）
CREATE TABLE task_links (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id INTEGER NOT NULL,
  kind TEXT NOT NULL,        -- 'mail' | 'calendar'
  ref_id TEXT NOT NULL,      -- mail: messages.id；calendar: 事件唯一键(ts+id)
  label TEXT,                -- 冗余展示用（主题/事件名）
  sub TEXT,                  -- 冗余展示用（发件人+时间 / 时间+地点）
  created_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_task_links_unique ON task_links(task_id, kind, ref_id);
```

### 4.2 行为变化（关键）
1. **不再自动生成待办**：删除同步后 / 摘要后的 `rebuildTasksForMessages` 调用（代码保留但不再触发；`source` 只允许 `manual`，
   卡片/摘要来源的旧数据在升级时**清空**，避免"默认全是别人的任务"）。
2. **显式创建入口**（都是用户主动点击）：
   - 待办页「＋ 新建待办」；
   - 邮件详情工具栏「＋ 加入待办」（带上这封邮件作为引用）；
   - 摘要行动项行尾「→ 待办」（把该行动项标题带来，用户可改）。
3. 引用邮件：待办编辑器内选择器（搜索最近 50 封 / 输入关键词），或从邮件详情直接创建。
4. 引用日历：从现有日历事件列表选（当前月/未来 90 天）+「自定义日期时间」。
5. 删除待办直接删（含其引用关系），不再有"重建后又出现"的问题（因为不自动重建）。
6. 一键已读等其它新功能独立，不在本方案内。

### 4.3 交互细节
- 新建：点「＋ 新建待办」→ 右栏空卡片聚焦标题；未写标题离开则不落库。
- 自动保存：标题/正文/清单变更 800ms 防抖保存；勾选立即保存并触发完成脉冲。
- 完成：勾选后从「今天/本周/全部」移出到「已完成」，可撤销（toast 里「撤销」）。
- 删除：二次确认（可设置里关掉「删除确认」）。
- 空状态：左栏空 → 「还没有待办 · 从邮件详情点「加入待办」开始」；搜索无结果 → 建议文案。

## 5. UI 打磨清单（#7）

| 项目 | 现状 | 改为 |
| --- | --- | --- |
| 间距 | 8px 堆叠、无呼吸感 | 4/8/12/16/24 栅格；卡片内边距 22px；列表行 11px |
| 圆角/边框 | 6px、纯灰边 | 12–14px 圆角；边框 `rgba(17,24,39,.08)`，卡片加 1px 内高光 |
| 阴影 | 无/重 | 两档：`0 1px 2px .05`（列表）/ `0 6px 20px .08`（详情卡） |
| 排版 | 字号混用 | 标题 19/680、小节 11/大写灰、正文 13/1.75、辅助 12/0.6 |
| 选中/悬停 | 无反馈 | 选中左侧 3px 竖条 + 淡底；悬停 120ms 背景过渡 |
| 动效 | 生硬 | 勾选脉冲 300ms、列表选中 120ms、页面切换已有 180ms 淡入 |
| 空状态 | 一行灰字 | 图标 + 标题 + 一句引导 + 快捷入口按钮 |
| 加载 | 空白 | 便签色骨架屏（3 行） |
| 其他页 | 未动 | 同步把收件箱/设置的主按钮、卡片圆角与间距对齐到同一套 token（小改动、可控） |

## 6. 实施计划（分两批，可分别验收）

**第一批（待办重做，约 1 天）**
1. 迁移 v22 + store/sqlite（tasks 扩展、task_links CRUD、清理自动来源数据）
2. 主进程 IPC：tasks 增删改查 + links 增删 + 邮件选择器数据源 + 日历事件选择器数据源
3. 渲染层：双栏待办页（列表 + 备忘录编辑器 + 清单 + 引用选择器 + 键盘/空状态/骨架屏）
4. 邮件详情「加入待办」、摘要行动项「→ 待办」
5. 单测（纯逻辑/存储）+ renderer E2E；删除旧的自动重建逻辑与相关测试

**第二批（UI 打磨，约半天）**
6. 抽取 design tokens（CSS 变量）+ 统一按钮/卡片/输入框
7. 收件箱/设置/详情页对齐间距与圆角；空状态与骨架屏
8. 截图对比（亮/暗）后交付

## 7. 验收标准

- [ ] 新装/升级后**待办默认是空的**，只有用户自己新建/从邮件创建的任务
- [ ] 待办可写标题、正文、清单；全部自动保存（关掉窗口再打开内容还在）
- [ ] 可引用 1–N 封邮件与 1–N 个日历事件，点「打开」能跳转
- [ ] 引用选择器能搜索邮件、能选日历事件、能自定义时间
- [ ] 今天/本周/全部/已完成 筛选正确，逾期红色
- [ ] 亮/暗两套主题视觉一致；空状态/骨架屏/完成脉冲可用
- [ ] typecheck + 单测 + renderer E2E 全绿；electron E2E 由 CI 跑

## 8. 需要你拍板的 4 件事

1. **布局**：A. 双栏备忘录（预览图，推荐）B. 便签墙（Google Keep 风）C. 保持单列列表、点开弹层编辑（改动最小）
2. **待办来源**：A. 纯手动（严格按你说的"自己添加"）B. **手动为主 + 两个显式入口**（邮件详情「加入待办」、摘要行动项「→ 待办」，推荐）C. 保留自动生成但加开关默认关
3. **引用方式**（可多选）：A. 邮件详情一键加入 B. 待办内搜索选邮件 C. 从日历事件列表选 D. 自定义日期时间
4. **UI 打磨范围**：A. 仅待办页 B. **待办 + 收件箱/设置的对齐**（推荐，工作量约 +半天）C. 全站重做（大工程，另排期）
